# Архитектура

## Потоки

```
Browser → Server Components / Server Actions → Supabase Auth + PostgreSQL RLS
Telegram webhook / admin manual import → telegram_messages → SQL trigger → work_queue
worker → ConservativeParser → store_parsed transaction → pending_moderation
admin → moderate_job transaction → published + notification queue
browser → product_id + job_id + idempotency_key → make_order → immutable price snapshot
sandbox signed event → verify HMAC → settle_payment transaction → promotion / placements
```

## Границы ответственности

- `app/`: маршруты, серверный рендеринг, API и действия форм.
- `components/`: интерфейс и небольшие client-islands; клиент не импортирует `service-db`.
- `lib/db.ts`: Supabase с пользовательской сессией. RLS применяется даже к прямым запросам PostgREST.
- `proxy.ts`: обновление cookies сессии; окончательная авторизация всегда на сервере и в SQL.
- `lib/service-db.ts`: привилегированный клиент только для backend/worker/scripts.
- `services/ai`: интерфейсы `AIProvider`, `JobParser`, `JobModerator`. Реализация по умолчанию детерминированная, не LLM.
- `services/telegram`: интерфейс источника, manual и Bot API. Polling-адаптер является альтернативой webhook, не запускается параллельно с ним.
- `services/payments`: заменяемый provider; только явно включаемый sandbox.
- `services/push`: ограничение адресов push-провайдеров для защиты от SSRF.
- `worker`: независимый процесс с доступом к Supabase, без бизнес-логики конкретного хостинга.
- `supabase/migrations`: схема, RLS, транзакционные бизнес-операции, индексы, очередь.

## Данные и происхождение

`telegram_messages` неизменяемы для обычных пользователей. Уникальность `(source_id, telegram_message_id)` защищает от повторной доставки. Повторный импорт того же номера не перезаписывает оригинал. Редактирования Telegram-сообщений этой версией не синхронизируются.

`jobs` хранит каноническую вакансию. `job_sources` хранит все исходные сообщения. SHA-256 отпечаток использует нормализованные название, описание, оплату, город, адрес, даты/время и контакты. Это строгая дедупликация, не нечёткий поиск похожих объявлений. Разные контакты/даты/оплата не объединяются. Перепубликация полностью одинакового текста старой истёкшей вакансии не продлевает её автоматически.

Город из настроек Telegram-источника используется как контекст источника и явно помечается для проверки. Парсер сам не угадывает город, адрес или работодателя. Отсутствующие значения остаются `null`. Координат нет.

## Статусы и квоты

Работодатель: `draft → pending_moderation`. Администратор: `published`, `rejected`, `draft` (запрос изменений), `archived`. Worker: `published → expired`.

`settings.publication` определяет число одновременно активных/ожидающих модерации бесплатных объявлений и срок публикации. Это не пожизненное число бесплатных публикаций. Запросы блокируют строку работодателя, чтобы параллельные отправки не превышали квоту. При исчерпании бесплатной квоты расходуется право из действующего пакета/подписки. Повторная отправка отклонённого объявления может потребовать ещё одно право, если бесплатная квота занята; эта коммерческая политика требует решения до реальных продаж.

Заказы хранят сумму в копейках и неизменяемый снимок продукта. Изменение цены в админке не меняет уже созданный заказ. Перечисление денег браузером не принимается. NORMAL является справочной записью; действующие условия бесплатной публикации меняются в `/admin/settings`, не через цену NORMAL.

## Поиск

Индексы PostgreSQL + `websearch_to_tsquery('russian',...)`. Порядок: релевантность, точное время публикации, коммерческий приоритет. Продвижение не ослабляет условия фильтрации. Минимальная сумма фильтрует **за смену**, чтобы 500 ₽/час и 60000 ₽/месяц не сравнивались с 4000 ₽/смена.

Поиск запускается отправкой формы, без запросов на каждый символ. Debounce для такого интерфейса не нужен. Вакансии возвращаются по 20, административные списки по 50. Поиски в профиле ограничены 50 записями. Справочники и редактор источников рассчитаны на небольшой MVP; административный редактор Telegram показывает первые 100 источников.

Относительные даты используют часовой пояс первого города. Расширение на города с разными поясами потребует передачи выбранного city timezone в `readFilters`; колонка timezone уже есть. Сохранённое «сегодня» становится конкретной датой, не движущимся расписанием.

## Очередь и доставка

PostgreSQL `FOR UPDATE SKIP LOCKED`; lease 5 минут, отдельный lock_token. Worker берёт одно задание непосредственно перед выполнением, batch ограничивает количество заданий за цикл. Повторы экспоненциальные, максимум 8 попыток. Ошибки доступны в админке. Исходные операции идемпотентны: уникальные сообщения, источники вакансии, события платежей и notification dedupe keys.

Push-транспорт имеет семантику at-least-once. IndexedDB в service worker и notification tag подавляют повторный показ одного ID. Строгое exactly-once между браузером, push-провайдером и сервером не обещается: авария между фиксацией ID и показом может потерять уведомление. Оригинал уведомления остаётся в кабинете.

## Расширение

MTProto, локальная LLM, настоящие платежи, автопродление подписки, скидки и дополнительные инструменты подключаются отдельными реализациями после проверки условий провайдеров. Их наличие не подразумевается текущими интерфейсами. Встроенная карта, чат, отклики, рейтинги и мобильное приложение не входят в эту версию.
