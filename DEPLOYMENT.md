# Размещение

## Сначала тестовый стенд

Не публикуйте этот архив как проверенный production без прохода QA.md. Нужны: реальный `npm install`, TypeScript check, `next build`, применение SQL, интеграционные тесты, мобильный браузер, проверка ролей и SMTP.

## Бесплатный старт

- GitHub: приватный репозиторий, без секретов. https://github.com/new
- Supabase Free: база, Auth, Storage в доступных лимитах. https://supabase.com/dashboard
- Netlify Free: совместимый с Next.js хостинг, допускающий коммерческое использование в пределах условий тарифа. https://app.netlify.com/
- Отдельный worker: первоначально ваш компьютер с Node.js и интернетом. После его выключения фоновые операции не выполняются; каталог скрывает истёкшие объявления по `expires_at` и без worker.

Vercel Hobby запрещает коммерческое использование: https://vercel.com/docs/limits/fair-use-guidelines. Для проекта с платным продвижением это не бесплатный production-вариант. Условия Netlify и лимиты проверяйте на дату развёртывания: https://www.netlify.com/guides/netlify-vs-vercel/.

Не обещается бесплатная круглосуточная эксплуатация без ограничений. При исчерпании квот бесплатные сервисы могут ограничить работу. Никакие платные дополнения или автопополнения включать не требуется.

## Web на Netlify

1. Загрузите код в свой репозиторий, добавьте проверенный lockfile после установки.
2. Создайте сайт из репозитория. `netlify.toml`: `npm run build`, `.next`, Node 22. Платформа должна распознать Next.js и применить свой адаптер.
3. В защищённых env-настройках сайта задайте переменные из SETUP. `NEXT_PUBLIC_APP_URL` равен реальному HTTPS-адресу сайта.
4. В Supabase Auth добавьте callback URL этого домена, настройте SMTP.
5. Соберите сайт. Проверьте `/`, `/jobs`, `/login`, регистрацию и private routes.
6. Только после этого регистрируйте Telegram webhook и включайте Push.

Бесплатный поддомен хостинга подходит для испытаний. Покупать домен ради карты не нужно. Для почты может потребоваться собственный подтверждённый домен или подходящий уже имеющийся отправитель.

## Worker и cron

```sh
npm run worker
# Один ограниченный цикл для планировщика:
npm run worker:once
```

Рабочий каталог должен содержать `.env.local`. Если env предоставляется процессу другим способом, запускайте `npx tsx worker/index.ts --once` без `--env-file`. Пример cron на вашей машине:

```
* * * * * cd /ABSOLUTE/PATH/podrabotka154 && /ABSOLUTE/PATH/node_modules/.bin/tsx --env-file=.env.local worker/index.ts --once
```

Пути заменяются фактическими. Cron не гарантируется на бесплатном веб-хостинге, и этот репозиторий не выдаёт постоянный worker за Netlify serverless-функцию. Для 24/7 нужен постоянно доступный исполнитель: собственная машина или подходящий бесплатный runner с проверенными условиями. Несколько worker допускаются благодаря row locks.

`WORKER_INTERVAL_SECONDS` управляет долгоживущим процессом, не расписанием внешнего cron. `WORKER_BATCH_SIZE` ограничивает количество заданий в цикле. Повторы до 8 попыток, затем разбор ошибки в админке.

## Эксплуатация

До запуска определите резервное копирование, восстановление, мониторинг очереди, ротацию секретов, аудит доступа и сроки хранения сырых Telegram-сообщений. Проверьте доступность иностранного хостинга из целевой сети и соответствие правилам локализации персональных данных. Free-tier Supabase не следует автоматически считать юридически подходящим для публичного российского сервиса.

Изображения ограничены 800 КБ. Используется Next Image, но внешние изображения здесь `unoptimized`, чтобы не зависеть от платного image CDN; полноценная перекодировка/удаление EXIF требует дополнительного этапа перед масштабированием.
