# Подработка 154

Исходники MVP v0.1 для поиска подработок, первый город: Новосибирск.

**Статус: рабочая ветка `render` для тестового контура, не production Vercel.**

## Что уже проверяется

GitHub Actions в ветке `render` выполняет `npm install`, TypeScript check, unit-тесты и `next build`. Публичный Telegram-импорт работает через серверный endpoint и консервативный парсер; вакансии не публикуются автоматически и попадают на ручную модерацию.

## Архитектура запуска

- **GitHub:** исходный код и CI, рабочая ветка `render`.
- **Render:** Next.js web service и отдельный cron для импорта публичного Telegram-канала.
- **Supabase:** PostgreSQL, Auth, Storage и очереди.
- **Vercel:** production-контур не используется для текущего тестирования.

## Возможности

- SSR-каталог подработки: поиск, категории, минимальная оплата, дата, адрес, источник, способ оплаты, занятость и сортировка.
- Детальная страница с реальными контактами и ссылками на 2ГИС/Яндекс Карты. Если адрес не указан, сервис не придумывает координаты и не показывает ложные метки.
- Supabase Auth: вход, регистрация, подтверждение email и восстановление пароля.
- Избранное, сохранённые поиски и добровольные Web Push-уведомления.
- Профиль работодателя, создание и редактирование вакансии, фото, предпросмотр и отправка на модерацию.
- Админка: модерация, справочники, источники Telegram, цены, лимиты и журналы.
- Публичный Telegram-импорт без необходимости владеть каналом: сохраняются оригинальные сообщения, затем консервативный парсер формирует кандидата на ручную проверку.
- Дедупликация Telegram-вакансий по исходному сообщению.
- PostgreSQL-очередь для фоновых задач; worker остаётся отдельным процессом для задач, которым нужен постоянный фон.
- Платные функции подготовлены через sandbox-механику, реальный платёжный провайдер не требуется для MVP.

## Первый Telegram-источник

Используется публичный источник `@rabota154NsK`. Импорт запускает `GET /api/telegram/import-public` с `Authorization: Bearer <CRON_SECRET>`.

Render cron вызывает этот endpoint каждые 15 минут. Наличие `render.yaml` не считается доказательством того, что Render уже синхронизировал cron: фактический статус проверяется в панели Render.

## Быстрый старт

```sh
npm install
npm run typecheck
npm test
npm run build
npm start
```

Для локального worker:

```sh
npm run worker
# или один цикл
npm run worker:once
```

Секреты не коммитьте в `.env.local`.
